# The hackathon, distilled

Source of truth: [Official Rules](https://github.com/microsoft/insidethegamehackathon/blob/main/OFFICIAL%20RULES.md)
in Microsoft's `insidethegamehackathon` repository. This page is our working summary. When the two disagree,
the Official Rules win.

## Dates (Pacific Time)

| Milestone | When |
| --- | --- |
| Registration closes | 20 October 2026, 12:00 |
| Submissions close | 27 October 2026, 23:59 |
| Our internal submission target | 26 October 2026 (one day of buffer; the video is recorded on 25 October) |
| Judging | 27 October to 10 November 2026 |
| Winners announced | by 20 November 2026 |

The hosted demo must stay up, free to use, until judging ends on 10 November.

## What we are entering

- **Category declared:** Best Enterprise Solution.
- **Also eligible for:** Grand Prize (judged across all entries regardless of category).
- A project can win one Grand Prize and one Category Prize.

## Judging criteria, equally weighted at 20% each

1. **Technological Implementation.** Creativity and optimised synthetic data creation; quality software
   development practices; effective use of the hero technologies; well-structured, documented, maintainable code.
2. **Agentic Design and Innovation.** Creative agentic patterns; sophisticated orchestration, MCP integration,
   multi-agent collaboration; novel or meaningfully improved AI implementation.
3. **Real-World Impact and Applicability.** Significance of the problem; deployable in production; impact on
   developers, businesses, end users.
4. **User Experience and Presentation.** Intuitive UX; a demo video that communicates value; a balanced blend
   of frontend and backend.
5. **Adherence to Hackathon Category.** Does the entry match the Best Enterprise Solution description:
   "strongest readiness for enterprise deployment and long-term business impact ... balancing innovation with
   the reliability, transparency, and controls required for use in production environments across global
   organizations."

Stage One is pass/fail on baseline viability: fits the theme, applies the required technologies.

## Hero technologies named in the rules

Microsoft Foundry, Agent Framework, Azure MCP, GitHub Copilot Agent Mode, Fabric, GitHub SDK, GitHub CLI,
Azure apps and AI services, Azure databases. See [MICROSOFT-INTEGRATION.md](MICROSOFT-INTEGRATION.md) for
what each one does in Pitchside.

## The five-stage pipeline the rules describe

Ingest synthetic events, interpret into statistics and patterns, explain why a moment matters, render for a
screen beside the match, personalise for an analyst and a casual fan as two genuinely different experiences.
The rules add: output should be "timed and machine-readable enough to be rendered as synchronized graphical
overlays on a live match feed".

## Hard constraints

- Synthetic, football-realistic data only. No footage or data is provided; we generate our own.
- The project must be new, created after registration opened on 29 September 2026.
- The repository must be public at submission.
- Demo video under two minutes, hosted on YouTube or Vimeo, no third-party trademarks or copyrighted music.
- All clubs, players, competitions and venues in Pitchside are fictional. No real club names, crests or player
  names anywhere in code, data, UI or video.
- Nothing in the project may reference betting or odds.
- English materials.

## Submission checklist

- [ ] Project pitch: what we built, which Microsoft and Azure technologies, what it does, what problem it solves.
- [ ] Demo video under two minutes, public URL.
- [ ] Public GitHub repository URL.
- [ ] Hosted demo URL, with credentials if gated, working until 10 November.
- [ ] README integration matrix and calibration report current.
- [ ] Category selected: Best Enterprise Solution.
